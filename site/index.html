03 · tipnotary innovation

The forgery lab

A four-block hash chain, live. Break it yourself and watch why "it verifies" is not the same as "it's true."

external anchor · sealed at page load · stored outside the chain visual

current tip:

Each block commits to the one before it: hash = sha256(msg + prevHash). Tampering with block 2 and recomputing only its own hash produces a self-consistent forgery — block 2 validates against its own message, yet block 3's stored prevHash no longer matches, so the chain breaks downstream. The obvious fix for a forger is the self-consistent rewrite: recompute every downstream hash so all the links line up again and the chain verifies cleanly. That is exactly the trap. Everything inside the chain is now internally true, and a naive verifier passes it. The only thing that catches it is the external anchor — a copy of the honest tip kept outside the chain, which the rewrite cannot reach. That is the whole tipnotary lesson: a ledger can prove consistency, but only an outside witness can prove it hasn't been forged.
